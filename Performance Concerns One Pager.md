  One common issue in any game with many npc’s at once is that they will gradually reduce performance as more spawn. While I don’t intend to have that many in my game, I already saw that the placeholder tank enemies can cause a minor decrease in performance with their rapid projectiles. A way to reduce this issue is to simplify their code as much as possible, reducing the resources each individual character uses and improving overall performance. Simplifying their models also helps to lower the resources they use. These issues tend to be fairly minor on each character (barring any egregious over-complications), but in any game with numerous enemies, like a horde shooter, they will cause serious issues, including freezing and crashing.
  
  The player’s device can often cause issues in newer games, as even simple looking games now tend to have more complex physics and logical calculations. This leads to cpu bottlenecking, hitting memory constraints, or the gpu simply not keeping up. The complex answer is to include optimization tools, issue detection, and improved memory management. The very straightforward answer is to not include the fancy modern graphics quality and stay with plainer or retro looking graphics. This is not inherently more optimized since modern game engines will require more resources regardless of the game’s graphical quality, but it will reduce the resources required and improve performance.
  
  Unity projects have a built-in memory leak reducer, Garbage Collection, but it’s not perfect, and the developers most prone to memory leaks are new developers who have never had to deal with them before. This can cause issue with performance as Unity projects have a memory pool that can request more memory to be allocated to it that can only increase over time. This means a memory leak will cause an increasingly large amount of memory to be allocated to the game, potentially maxing out the device’s memory. Luckily Unity has a built-in tool to check for memory leaks, as well as a newer optional tool which is seemingly better. These let you run part of a game and will tell you if there is a leak, and what that leak is, allowing you to go back into your code and try to fix the specific issue quickly.
  
  Largely due to the scope of my game, I intend to keep the enemies and models as simple as possible. Hopefully, due to the simplicity of my game, I won’t run into most of the performance issues, but intentionally keeping it simple should also help keep things running smoothly. I will also run Unity’s memory leak checker, since that could cause issues (and it is overall good form to check), but I don’t anticipate anything severe. The main worry I have on all fronts is that the projectiles could both lag the game down and cause a memory leak, since they can be spawned infinitely and rapidly. If they have any issues whatsoever with performance there is a solid chance they will be the single largest contributor to performance issues.
