Game Design Principles for Unnamed Game Concept
By Trey Hansen
Summary
This document describes multiple game design principles used by game developers, their pros and cons, and how they may be integrated into a game I will develop.
Game Design Principles
Game design principles are guiding ideas used to ensure a game is high quality and fun to play. One important principle is designing the game around a core mechanic. Tetris is a popular classic because it followed this mechanic, as its gameplay is incredibly simple; players simply rotate and stack chunks of blocks. While this principle will almost force developers to create a solid core mechanic, ensuring there is at least one good thing in the game, if the core mechanic doesn’t appeal to a player, the game likely will not resonate with them, since that mechanic will be the primary focus of the game. 
Another principle that synergizes with core mechanics is designing the game holistically. A holistic game’s features will all connect and interact with each other, allowing each feature to add to the core experience without detracting from another. One game that does this well is Stellaris, as each feature is designed to interact with building your empire. Wars, diplomacy, resources, and other player-facing features can all either help or hinder you, and will all need interaction from other features, such as a war requiring alloys for ships, which can be obtained by trading. The main issue with this is that it is very hard to do, as you need to constantly ensure every mechanic is integrated, which may cause players to need to juggle many game mechanics at once.
In creating a holistic game, designers will likely work towards a third principle, balancing gameplay options, which simply means giving the player equally viable ways to utilize all the options they have for completing game tasks. A game series that does this exceptionally well is the Dishonored series. Players are given tools to complete missions via stealth or combat, and the difficulty largely increases for the approach the player takes. This forces players to either upgrade their skills and equipment or change their approach, rewarding them for whichever choice they make. The downside to this is that there will always be some “optimal” approach, and players may get angry if you try to balance other options when they have chosen the “best” one.
Possible Integrations
I intend to create a twin stick shooter-esq core gameplayer loop, with everything else revolving around that, so I will certainly have a core game mechanic. Holistic game design is mostly a problem for larger games with more mechanics, so I likely will not run into an issue with it if I keep feature creep to a minimum. As of now I am envisioning this as a rogue-like, with semi-random upgrades, so I will have numerous build options I will need to balance. I see this being the hardest principle for me, but also the most important, as many of these sorts of games have an issue with strong metas, but players (including myself) enjoy the ability to make very strong builds. My focus therefore will primarily be on allowing non- “meta” builds to still be viable.
